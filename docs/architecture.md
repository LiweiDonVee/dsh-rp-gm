# GM architecture

The plugin registers one public `rp-gm` preset. Its persona describes the native GM protocol; scope-bound tools are owned by each bound Agent. The preset, tools, prompt contexts, event observers, owner Connection routes and streams all have unload disposers.

`core.mjs` validates immutable reviewed inputs and typed scene/facts. `session.mjs` derives actual assistant/tool/turn sources and folds effective surfaces, including compaction and content replacement. `store.mjs` has one atomic metadata writer queue per directory; it stores launch fingerprints and identities before invoking external startup steps. It never stores mutable fact entries.

`host.mjs` resumes startup from durable checkpoints. The requested session ID is allocated before create and looked up before retrying create. A normal session/prompt uses one stable requestId. No product code appends Session events; the host creates its protected initial system head and owns all tool/call/result publication.

`runtime.mjs` binds Database factAccess to actual session/Agent ownership. Fact source is `{assistantMessageId,callId,callSeq,turnStartSeq}` and turnKey is exactly JSON.stringify([sessionId,turnStartSeq]). Database persists the operation batch and receipt together. Opening tools accept no model seed. The metadata layer may retain only receipt/source pointers to recover a lost response. Inactive pointer lookups never revive a rewound receipt.

Accepted opening detection prefers LastStep.narratives. The standalone parser verifies effective canonical tool identity and explicit `meta.rpLastStep.record.factReceiptId`; prose text is never evidence of opening. Receipt.kind is verified through the current story's Database facade. A new presentation is refused if its receipt is superseded or already has an accepted canonical narrative. LastStep handles same-context complete reservations and failed rewrite families before invoking the fresh-presentation seam.

`branches.mjs` uses public session/fork. `rollback.mjs` replays both normalized durable inbox lists, matches the factual turn's first claim to canonical user MessageIds/source, and tracks edits to each pending instance's initial enqueue. Rollback chooses the latest earlier closed, empty-inbox prefix that retains the opening and every prior completed turn; non-isolatable inputs reject before fork. It rechecks the source immediately before dispatch, never clamps to inherited end-seed/count and never clears an inbox or edits seed records. The parent is preserved. LastStep.inheritSession owns historical profile/overlay selection, Database owns causal fact inheritance, Context owns its own projected plan. GM does not clone their internal stores. Reserved restore jobs gate play through native pre-step admission and direct factual/presentation operations; activation validates required state before clearing the matching gate.

A restoring child remains gated during ordinary binding/state observations. Only a successful branch setup or setup retry moves it back to starting, after which canonical opening observation may mark it active. Native pre-step retries the existing setup path and rejects admission while an installed dependency still fails; explicit restore reservations are not cleared by that retry. Receipt discovery skips historical selectors only when Database explicitly reports INACTIVE_SOURCE, preserving all other dependency errors and current causal facts.

The native owner panel has a static original sample with two exact openings and a builtin LastStep profile containing only simple prose rules. Fixed character/persona source context is distinct from current Database facts. Optional service absence remains visible as an operation-specific diagnostic while the library is usable.

`transfer-schema.mjs` validates the owner envelope, fixed binding/launch fields, identities and ancestor closure. `transfer.mjs` exports only selected metadata, checking idle Agents, an atomic store snapshot and unchanged canonical source/revision. The coordinator owns cross-owner `Agent.runMaintenance`; GM never acquires it recursively. Cold snapshots use authenticated owner readers without manufacturing an Agent.

Restore checks the existing restore identity before deeper schema/revision/proof work. The same store queue validates real imported headers/events, Database effective sources/refs and LastStep canonical opening narratives before a single atomic merge. Failed proof does not reserve a payload fingerprint or increase revision. Existing unrelated bindings survive. The coordinator's explicit reservation is a separate earlier execution gate.

Pre-resume proof uses Database.effectiveV2 and LastStep owner methods. After safe no-prompt resume, activation uses the actual registered Agent's factAccess to validate current receipts, kind, ownership, active sources and state-ref versions. A parent-future lastReceiptId hint absent from the child prefix does not override the actual current receipt. Current/opening evidence must still pass. Partial restore remains gated; no historical model/tool replay occurs.

StoryBinding.profile is immutable launch provenance. Export/restore require its exact retained version; the coordinator includes it using LastStep.exportState additionalProfileRefs. Actual style/overlay comes exclusively from LastStep.state and LastStep.inheritSession. Activation validates that current binding's ready profile and native admission, allowing a legitimate owner rebind to another ready style.

StoryBinding.sources is also immutable launch provenance. Database owns its actual current source composition, including legal document additions and compatible owner reconfiguration. GM validates the current v2 fact binding, exact registered fact refs and effective state without comparing the current source list to launch sources. sources.mjs resolves every initial database ID/version through the public owner reader; missing exact versions remain requirements. The coordinator retains those passive initial versions via Database.exportState additionalDatabaseRefs. GM never rebinds the current source list to satisfy provenance.

Native error presentation uses the public tool definition.finalizeContent(exec,result). Known safe kernel errors preserve the native error outcome while projecting code/message/receiptId into untouched default content. The SDK's error/meta/value and post-policy content remain authoritative; unknown errors and redactions are not rewritten.

Unit/service tests use explicit fixtures. The separate scripts/native fixture installs immutable SHA-named tgz inputs in isolated official rc.3 homes. Only its local model adapter and explicit fault injection are synthetic. Product GM/Database/LastStep/Loop services, native tool execution, canonical persistence, fork/rollback and owner transfer run from actual installed artifacts. Its transport coordinator is test infrastructure; StoryKit supplies the complete product save/restore workflow.
